## 3. [IMPLEMENTED] Frame & Jank Metric Semantic Disambiguation

1. **SurfaceFlinger Presented FPS**:
   - **Definition**: Rate of unique composited frame presentations to the host display swapchain (`deltaTotalFrames / deltaSeconds`).
   - **Meaning**: Measures real end-to-end presentation throughput on the Windows display surface.
2. **HWUI Frame Latency (`FrameCompleted - IntendedVsync`)**:
   - **Definition**: The duration between Android Choreographer intended Vsync and the GPU rendering completion of that frame by Skia/HWUI.
   - **Meaning**: P50 (25.48 ms) and P90 (28.15 ms) reflect internal rendering pipeline queue depth (2-frame pipeline queue in QEMU GLES translation).
3. **SurfaceFlinger Presentation Frames (`totalFrames`) vs FrameTimeline Tokens (`totalTimelineFrames`)**:
   - `totalFrames` tracks SurfaceFlinger hardware/GLES swapchain presentations. `totalTimelineFrames` tracks Android 14 Choreographer frame deadline tokens registered by HWUI. They are separate pipeline metrics and must not be conflated.
4. **Official SurfaceFlinger FrameTimeline Jank %**:
   - **Definition**: Directly parsed from `dumpsys SurfaceFlinger --timestats` (`deltaJankyFrames / deltaTotalTimelineFrames`).
   - **Classification Insight**: In the emulator pipe transport, 2-frame queuing causes frame duration to exceed 16.67ms, which FrameTimeline categorizes as `appBufferStuffingJankyFrames` and `sfPredictionErrorJankyFrames`. Crucially, SurfaceFlinger steadily presents all 1,800 frames per trial at **60.00 FPS with 0 dropped frames**.
5. **Diagnostic Latency Threshold**:
   - The diagnostic metric previously labeled "Jank %" is renamed to `LatencyOver16_67Percent`.

## 4. [IMPLEMENTED] Fail-Closed Graphics Configuration Auto-Remediation & Verification

In `scripts/windows/run-spike.ps1`:
- Inspects `hw.gpu.mode` and `hw.gltransport` from `$env:USERPROFILE\.android\avd\<AvdName>.avd\config.ini`.
- If either value diverges from `host` or `pipe`, normalizes the configuration.
- **Post-Remediation Strict Verification**: Re-reads `config.ini` and verifies `hw.gpu.mode == host` and `hw.gltransport == pipe`. If verification fails or file write fails, the script fails fast (`throw [FATAL] ...`).
