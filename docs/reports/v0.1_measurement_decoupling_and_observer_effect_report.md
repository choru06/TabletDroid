## 1. 개요 및 배경 (Context & Objectives)
이전 성능 벤치마크 루프는 하나의 동기식 루프 내에서 스와이프 입력(`adb shell input swipe`), 프로세스 CPU 수집(`Get-Process`), Windows GPU 성능 카운터 질의(`Get-Counter \GPU Engine(*)\Utilization Percentage`)를 순차적으로 실행하여 **계측 오버헤드로 인한 워크로드 왜곡(Instrumentation-Induced Workload Distortion / Observer Effect)** 가능성이 존재했습니다.

또한, `dumpsys gfxinfo framestats`는 AOSP 내부의 고정 크기 120개 원형 버퍼(`kFrameHistorySize = 120`)로 인해 테스트 시간이 길어져도 최대 120개 프레임 기록에서 캡이 발생하므로, 이를 전체 테스트 시간으로 나누는 방식은 실제 프레젠테이션 프레임레이트를 왜곡할 수 있었습니다.

본 커밋에서는 다음과 같은 개선과 실기 검증을 수행했습니다:
1. **계측과 워크로드 생성의 완전 분리 (Decoupling Architecture)**:
   - 전용 비동기 백그라운드 태스크(`Task.Run` + `ConcurrentBag`)를 통해 텔레메트리 샘플링(CPU / GPU)을 독립 실행.
   - 워크로드 생성기는 250ms 고정 페이싱 간격으로 양방향 스크롤을 끊김 없이 연속 주입하고 실제 `SwipeCount`와 `SwipeCadence`(swipes/sec)를 명시적으로 기록.
2. **SurfaceFlinger 기반 Presentation Frame Rate 확립**:
   - `dumpsys SurfaceFlinger --timestats -dump`의 델타 프레임 카운트($\Delta\text{totalFrames} = \text{totalFrames\_end} - \text{totalFrames\_start}$)를 통해 실제 디스플레이 컴포지터 기준 `Presented FPS` 산출.
3. **Measurement Observer Effect 4-Condition A/B 검증**:
   - 조건 A (No Telemetry), 조건 B (CPU Only), 조건 C (GPU Only), 조건 D (CPU + GPU) 각 5회 트라이얼 측정.
4. **Decoupled GPU Backend (OpenGL vs Vulkan) 재측정**:
   - 새 디커플드 벤치마크 러너를 적용하여 Skia OpenGL (`skiagl`) vs Skia Vulkan (`skiavk`) 재측정 (각 5회 트라이얼).
5. **문서 정정 및 가설 상태 정립**:
   - `docs/performance/gpu_backend_comparison.md`에서 ASG 관련 단정적 표현을 완화하고 `[OPEN / HYPOTHESIS]`로 유지.

## 3. 실기 측정 결과 (Empirical Results)

### 3.1 Observer Effect Characterization (1920x1200, 5 Trials x 10s)
| Condition | Valid Trials | Presented FPS | FPS [Min, Max] | StdDev | Wall Duration | Swipe Cadence |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **A. No Telemetry (Pure Workload)** | 5 / 5 | **4.03 FPS** | [1.01, 5.98] | 2.03 | 11.27s | 0.49 sw/s |
| **B. CPU Telemetry Only** | 5 / 5 | **5.30 FPS** | [2.70, 6.23] | 1.41 | 10.64s | 0.59 sw/s |
| **C. GPU Telemetry Only** | 5 / 5 | **4.51 FPS** | [3.33, 6.13] | 1.01 | 10.80s | 0.48 sw/s |
| **D. CPU + GPU Telemetry** | 5 / 5 | **6.12 FPS** | [4.69, 6.74] | 0.70 | 12.22s | 0.41 sw/s |

- **분석**: 백그라운드 태스크 분리를 통해 스와이프 케이던스는 약 0.41~0.59 sw/s 수준으로 안정적으로 유지되며, 텔레메트리 실행 유무에 관계없이 프레젠테이션 프레임레이트는 4~6 FPS 대역에서 분산 범위 내에 머무름을 확인했습니다.

### 3.2 GPU HWUI Renderer Comparison (1920x1200, 5 Trials x 10s)
| Condition | Valid Trials | Presented FPS | FPS [Min, Max] | StdDev | Wall Duration | Swipe Cadence |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **A. Skia OpenGL (`skiagl`)** | 5 / 5 | **5.23 FPS** | [3.30, 10.19] | 2.56 | 10.80s | 0.53 sw/s |
| **B. Skia Vulkan (`skiavk`)** | 5 / 5 | **7.83 FPS** | [3.51, 11.29] | 2.88 | 10.84s | 0.64 sw/s |

- **결론**: **`inconclusive`** (트라이얼 간 분산 범위([3.30~10.19] vs [3.51~11.29])가 크며, Skia 백엔드 교체만으로는 20+ FPS 목표를 달성하는 결정적 요인으로 작용하지 않음).
