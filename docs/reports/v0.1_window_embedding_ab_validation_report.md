## 3. 🎯 [INFERENCE] 가설 검증 및 결론

* **가설**: *"SetParent Win32 임베딩이 프레임버퍼 IPC를 우회하여 60~120fps를 달성할 것이다."*
* **실측 검증 결론**: **【 가설 기각 (Refuted as Performance Solution) 】**
  * Standalone (15.5 FPS) 대비 Embedded (13.0 FPS)로 프레임레이트는 대등한 수준(오차 범위 ±2.5 FPS)을 보였습니다.
  * 따라서 **`SetParent` 윈도우 임베딩은 호스트 UI 안에 에뮬레이터 툴바/창 테두리 없이 매끄럽게 넣는 최고의 `UX Integration` 도구**이지만, **1920×1200 해상도에서의 15~20fps 렌더링 병목 자체를 해결하는 열쇠는 아닙니다.**
  * 진짜 병목은 윈도우 DWM 레이어가 아닌 **안드로이드 게스트 그래픽 서브시스템(`gfxstream` GLES-to-Direct3D11 번역, SurfaceFlinger Vsync 페이싱)** 내부에 존재함이 명확해졌습니다.

## 4. 🚀 [DECISION] 향후 아키텍처 의사결정

1. **`IWindowEmbedderService`는 TabletDroid Host의 공식 UX 뷰포트 통합 엔진으로 유지/채택**합니다.
2. **성능 병목 해결을 위해 다음 단계는 에뮬레이터 내부 GPU 렌더링 백엔드 옵션 조사로 전환**합니다:
   * `-gpu host` vs `-gpu angle_indirect` vs `-gpu vulkan`
   * 게스트 `SurfaceFlinger` 버퍼 큐 및 리프레시 레이트 설정 최적화.
